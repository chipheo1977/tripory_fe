# Phase 5.1 Plan 02: Checkpoint BE like và comment Summary

**BE like/comment được chấp nhận theo xác nhận của người dùng; hợp đồng ghi lại các thay đổi khi triển khai BE và ngày deploy. Agent không kiểm độc lập các dòng của mục 11.**

## Do người dùng xác nhận (agent chưa kiểm độc lập)

- Code BE like/comment đã commit và push đúng nhánh Render deploy; đã deploy lên `https://tripory-be.onrender.com`.
- DB nằm trên Neon. Migration `20261113103118_Add_Itinerary_Likes_Comments` chạy thử trên một branch Neon trước, rồi chạy lên branch production.
- Người dùng tự kiểm thấy GET chi tiết lịch trình đã xuất bản hết lỗi 500.
- Mục "Thay đổi so với hợp đồng khi triển khai BE (2026-11-13)" của hợp đồng: PUT like dùng `INSERT ... ON CONFLICT DO NOTHING`; `pageSize` của GET comments là 1..50; POST comments trả 201 không có header `Location`; rate limit phân vùng `user:{id}`, không có claim thì `ip:{ip}`; thứ tự middleware `UseAuthentication` → `UseRateLimiter` → `UseAuthorization`; xóa comment là xóa hẳn; đề xuất (a)..(f) xác nhận.
- Các dấu `- [x]` ở mục 11 (15 dòng) được tích theo xác nhận của người dùng, không phải kết quả agent đo.

## Kiểm độc lập

Người dùng chọn bỏ qua kiểm GET độc lập và kiểm các dòng cần token. Trước khi chỉ thị bỏ qua tới nơi, agent đã gọi 3 GET chỉ đọc, không token, vào lịch trình đã xuất bản `be03d53a-bc7e-409b-8aeb-58188bd9370f` (2026-11-19):

| Request | HTTP | Kết quả |
|---------|------|---------|
| `GET /api/v1/itineraries/{id}` | 200 | chi tiết trả về bình thường |
| `GET .../like` | 200 | `{ likeCount: 0, likedByMe: false }` |
| `GET .../comments?pageIndex=1&pageSize=10` | 200 | `items` rỗng, `pageSize` 10, `hasNextPage` false |

Không gọi bản nháp, id không tồn tại hay endpoint ghi. Không ghi dữ liệu.

## Bài học: migration không tự chạy khi deploy

- Lỗi trước đó là Postgres `42P01` `relation "itinerary.itinerary_likes" does not exist` (500 ở GET chi tiết): code mới đã deploy nhưng bảng chưa có.
- BE không tự chạy migration lúc khởi động (Dockerfile chỉ chạy API). Deploy Render chỉ đưa code mới, nên mỗi migration phải chạy tay `dotnet ef database update` bằng chuỗi kết nối direct (không pooled) của Neon.
- `dotnet ef` dựng host qua `Program.cs`, nên ngoài `ConnectionStrings__DefaultConnection` còn cần `JwtOptions__SecretKey` tạm, tối thiểu 32 ký tự; thiếu thì báo "Unable to create a 'DbContext'".
- Gợi ý (không bắt buộc, agent không sửa `tripory_be`): thêm bước migrate vào quy trình deploy BE, ví dụ một job chạy migration trước khi Render chuyển sang bản mới.
